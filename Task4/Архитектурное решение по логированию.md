# Архитектурное решение по логированию
- Где собирать: <br>
Интернет-магазин, CRM, MES — везде, где есть заказы и клиенты.

Список логов:  
- INFO:
    - Изменение статуса заказа (время, заказ id, покупатель id).
    - Успешная оплата (время, заказ id, сумма).
    - Уведомление клиента (время, канал отправки, статус).

- WARN:
    - Внешний сервис медленно отвечает.
    - Повторные попытки

- ERROR:
    - Ошибка сохранения заказа.
    - Падение внешнего API.


## Мотивация
- Инициация диагностики. Не нужно дожидаться пока клиент пожалуется.
- Меньше нагрузки на поддержку.
- Уменьшение времени восстановления сервисов.
- снижение процента потерянных заказов.


## Предлагаемое решение
Применим ELK стек: 
- **Filebeat**: Агент, отправляющий логи с различных серверов в Logstash.
- **Logstash**: Серверный конвейер, обрабатывающий данные и передающий их в Elasticsearch.
- **Elasticsearch**: Документоориентированная NoSQL база данных, хранящая данные в формате JSON и обеспечивающая быстрый поиск с помощью различных структур данных.
- **Kibana**: Инструмент для визуализации данных из Elasticsearch, позволяющий создавать интерактивные графики и дашборды.

В приоритете будет интернет-магазин, т.к. с ним клиенты взаимодействуют больше всего.

## Алертинг и анализ

- Было четыре записи о создании заказов и за секунду их стало 10 000. Возможно, происходит DDoS-атака конкурентами.
- всплеск ошибок
